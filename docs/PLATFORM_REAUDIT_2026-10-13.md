# 마케팅 플랫폼 재점검 — 2026-10-13

## 결론

현재 서비스는 블로그 중심 초안 생성·직접 게시 보조와 일부 주문 집계 도구다. 채널 이름이 많다고 해당 플랫폼의 신기능·공식 자동 게시·성과 수집을 지원하는 것은 아니다. 네이버의 AI 검색과 플랫폼 자체 AI 도구가 확대된 상황에서는 **확인된 매장 정보 → 채널별 유용한 초안 → 실제 게시 확인 → 문의·예약·주문 결과**의 연결이 우선이다. 이는 이번 조사에 따른 제품 방향 제안이며, 성과 개선을 실측한 결과는 아니다.

27개 채널 선언, 콘텐츠 생성 대상 9개, backend 어댑터 7개를 코드에서 확인했다. live/wip/planned는 내부 표기다. 이번에 실제 고객 계정으로 27개 기능이 작동하는지 시험한 것은 아니다. 기존 10월 8일 생성·비공개 게시 증거와 이번 공식 문서·코드 검사를 구분한다.

## 코드에서 발견한 잔여 위험

1. 플레이스/리뷰 수집이 변동 가능한 화면 셀렉터와 브라우저 워커에 의존한다. 리뷰 0건을 반환하면 실제 무리뷰와 수집 실패를 구분하기 어렵다. URL 파서는 `/place/숫자` 위주여서 restaurant/hairshop 등 URL 형식도 검사해야 한다. 이번엔 실제 브라우저 수집을 실행하지 않았다.
2. Instagram은 formatter가 본문에 태그를 붙이고 자동 게시 adapter가 tags를 다시 붙이는 경로가 있다. 게시 URL도 API 미디어 ID를 shortcode처럼 사용한다. 계정이 연결돼 있지 않아 자동 게시 통과 증거 없음.
3. 스마트스토어는 조회 기준이 변경일이고 그래프는 주문일로 묶는다. ‘해당 기간 매출’ 정의와 지급/취소/반품, 오래된 주문 변경을 대사해야 한다. 이번 페이지 수정만으로 매출 정확성 전체가 검증된 것은 아니다.
4. 사진 EXIF와 원문 리뷰를 활용하는 프롬프트가 있다. 고객 데이터 전달 범위와 보관·최소화는 별도 재점검 대상으로 남긴다.
5. 공지·권한·모델 목록의 확인 날짜와 적용 조건을 코드와 함께 관리해야 한다. 단위 테스트 통과만으로 외부 플랫폼 정상·노출 성과를 판정하지 않는다.

## 이번 수정과 검증

- 생성 지침에서 확인되지 않은 알고리즘·체류시간 보장과 실제처럼 경험 창작하는 지시를 제거했다. 확인된 정보와 핵심 답을 우선하도록 보완했다.
- 블로그 확장 ‘30초 발행 검증됨’ 문구 제거, 알림톡의 광고성 용도 설명 정정.
- 스마트스토어 변경주문 more 커서 처리, 페이지 반복·상한 도달 시 부분 집계 성공 금지. 가상 345건과 페이지 중복 주문을 모두 집계하는 테스트 및 반복 커서 실패 테스트 추가.
- `npm run check`: 263개 테스트 통과, 타입·전체 빌드 성공, 의존성 취약점 0.
- 운영 health 조회 HTTP 200, DB 응답 정상. 10월 13일 GitHub 실행 상태에서 생성·리뷰 수집·아침 검증 성공, 인증 설정 점검 실패를 확인했다. 상태만 읽었으며 실제 메일·외부 게시·계정 권한까지 확인한 것은 아니다.
- 유료 생성, 고객 메시지/게시, 고객 DB 수정, 워커 재가동 없음. 이번 수정은 로컬 검토 상태이며 운영 재배포하지 않았다.

## 적용 순서

1. 이번 사실성·설명·집계 수정 검토 후 운영 반영. 기존 복구 메일 실패 해결은 계속 출시 차단 항목.
2. 네이버 URL/수집 실패 구분과 최신 편집기 실제 검증. 실제 매장 정보의 수집일·확인일을 표시하고 오래된 가격/시간을 게시 전에 확인.
