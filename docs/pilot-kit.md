# 파일럿 온보딩 키트 (8/20~)

사장님을 초대할 때 그대로 복사해 쓰는 문서. **지금 실제로 되는 것만 약속한다** — 카톡봇·알림톡 자동발송·인스타 API 발행은 아직 없으므로 초대문구에 넣지 않는다.

## 1. 카톡 초대 메시지 (복사용)

> 사장님, 안녕하세요! 요즘 가게 홍보 글 쓰실 시간 없으시죠.
>
> 제가 만들고 있는 **마케팅올인원**을 3개월 무료로 먼저 써보실 분을 찾고 있어요.
>
> 하는 일은 딱 이겁니다:
> - **매일 아침 9시 전에**, 우리 가게 얘기로 쓴 글이 채널별로 준비돼 있어요 (실제 가격·영업시간까지 넣어서, 매일 다른 각도로)
> - 사장님은 **오늘 하나만** 골라 붙여넣으면 돼요 — 30초면 끝 (뭘 먼저 할지도 알려드려요)
> - 네이버 리뷰도 매일 자동으로 모아서 **답글 초안**까지 써둡니다
> - 한동안 안 오신 단골에게 보낼 **재방문 문자**도 만들어드려요
>
> 계정은 제가 미리 열어드릴게요. 들어가셔서 가게 이름이랑 네이버 플레이스 주소만 넣어주시면 됩니다 (1분).
>
> 써보시고 매주 한 번씩 불편한 점만 알려주시면 돼요. 3개월 뒤에 계속 쓸지는 그때 정하시면 됩니다.

### 초대 절차 (운영자, 사장님 1명당 10초)

```bash
cd backend && npx tsx src/invite-owner.ts 사장님이메일@naver.com "쿵더쿵 사장님"
```

출력되는 "📋 카톡에 그대로 붙여넣기" 블록을 위 초대 메시지 뒤에 붙여 보내면 끝.
사장님은 **링크 한 번 누르고 비밀번호만 정하면** 바로 온보딩으로 들어간다
(2026-08-06 운영에서 전 경로 완주 검증: 링크 클릭 → 비밀번호 설정 → 온보딩 5스텝 → 웰컴 초안).

> ⚠️ 스크립트가 "임시 비밀번호 방식으로 안내합니다"를 출력하면 **링크가 죽은 것**이다.
> Supabase 리다이렉트 허용목록에 운영 주소가 빠진 상태이니 먼저 고칠 것
> (`npx tsx src/check-auth-config.ts`로 확인). 그 상태로도 임시 비밀번호로는 들어갈 수 있다.

**왜 자가가입을 안 시키는가(실측)**: Supabase 내장 메일은 프로젝트 전체 **시간당 2통**이고
팀 멤버가 아닌 주소로는 발송 자체를 거부한다. 확인메일이 켜져 있어서, 사장님이 직접
가입 버튼을 누르면 `429 over_email_send_rate_limit`로 **계정조차 만들어지지 않는다**.
커스텀 SMTP(Resend 등)를 붙이면 자가가입으로 되돌릴 수 있다 —
그때 `CUSTOM_SMTP_CONFIGURED=true`를 켜면 매일 도는 인증 점검도 통과로 바뀐다.

## 2. 가입 후 일어나는 일 (사장님 안내용)

1. **링크 → 비밀번호 → 매장 등록 (1분)**: 가게 이름 → 업종(43종) → 파는 것 두세 개 → 네이버 플레이스 주소 → 채널 확인.
   화면 문구는 업종에 맞춰 바뀐다(미용실이면 "어떤 **시술**을 파세요?"). 중간에 새로고침해도 입력이 남아 있어요.
2. **바로**: 첫 초안이 자동으로 만들어져 대시보드에 등장 (~1분 내. 늦어지면 "지금 첫 글 만들기" 버튼이 떠요)
3. **매일 아침**: 9시 전에 새 초안 준비(연결한 채널 전부) + 리뷰는 하루 3회(오전·점심·저녁) 자동 수집
4. **사장님이 할 일**: 대시보드 맨 위 **"오늘 하나만 한다면"** 카드에서 [붙여넣기 →] →
   화면 순서대로 **[1. 앱 열기] → 붙여넣기 → [2. 붙여넣었어요]** (블로그 1분, 나머지 30초).
   채널을 여러 개 연결해도 매일 다 할 필요 없다 — 1순위 하나만 해도 되게 골라준다.
5. **한동안 안 온 단골**: `/regulars`에 이름·번호·마지막 방문일을 넣으면 재방문 문자 초안이 만들어진다.
   **[문자로 보내기]를 누르면 문자 앱이 번호·내용까지 채워져 열린다** (알림톡 없이 지금 바로 됨).

## 4. 예상 질문(FAQ)

**Q. 인스타는 자동으로 올라가나요?**
아직요. 캡션을 자동으로 만들어 드리고, 복사해서 붙여넣으시면 됩니다. Meta 공식 API 연동은 준비 중입니다.

**Q. 매일 비슷한 글이 나오는 거 아닌가요?**
매일 각도(대표메뉴·분위기·팁…)×제목 구조×중심 소재를 바꿔서 씁니다. 한 달 동안 같은 조합이 반복되지 않게 설계돼 있어요.

**Q. 글 말투가 우리 가게랑 안 맞으면요?**
리뷰에서 매장 톤을 학습하지만, 안 맞으면 알려주세요. 피드백이 다음 글에 반영되도록 조정합니다.

**Q. 단골 알림톡은요?**
메시지 초안까지는 지금도 만들어 드립니다(`단골` 메뉴). 자동 발송은 알림톡 채널 심사가 끝나면 열립니다.

**Q. 내 가게 정보는 어떻게 관리되나요?**
개인정보처리방침(사이트 하단)에 그대로 적혀 있습니다. 탈퇴하면 설정 화면에서 즉시 전부 삭제됩니다.

**Q. 돈은 정말 안 내나요?**
3개월 파일럿 기간은 완전 무료입니다. 유료 전환은 최소 30일 전에 안내하고, 동의 없이 결제되는 일은 없습니다(이용약관 3조).

## 5. 운영 메모

- **Gemini 한도(실측)**: flash 무료 = 프로젝트당 **20회/일**. 데일리 크론은 매장당 flash 2회(기획+본문; 채널 네이티브 재작성은 lite 별도 쿼터) → **크론만이면 최대 ~10매장**, 사장님 수동 생성 여유를 두면 **6~8매장 권장**. 초과분은 flash-lite로 자동 폴백돼 끊기진 않지만 품질이 살짝 낮아짐 → 그 전에 Gemini 유료 전환.
- **감시는 자동**: 06:00 생존확인 → 07:30/08:30 생성(2중) → 09:30/10:30 "초안 실존" SLA 검증(2중) → 실패 시 GitHub 이슈→이메일. 조용하면 전부 정상.
- demo 계정(demo@example.com)은 파일럿 시작 전 데이터 정리 여부 결정. 정리하기로 하면:
  `cd backend && npx tsx src/reset-store-data.ts --wipe-posts --yes` (글·활동만) 또는 `--full --yes` (리뷰·단골까지).
  기본은 드라이런(현황만), 삭제 전 `backend/backups/`에 자동 JSON 백업. 매장 설정·계정은 유지된다.
- 소셜 로그인(카카오)은 등록되는 대로 가입 문턱이 더 낮아짐 — 초대 전 켜두면 좋음(`docs/oauth-setup.md`).
- 이메일 확인이 켜져 있으면 가입 후 메일 인증이 필요 — 파일럿 전 Supabase에서 확인메일 OFF 권장(초대 문턱↓).
