## 9/10에 한 것

**① 두 흐름 구분을 코드가 지킨다** — `check-operator-leak.ts` 가 고객 `.tsx` 52개를 훑어
`prebuild` 에서 빌드를 막는다. 첫 실행에 걸린 3건은 문구를 지우지 않고 **코드를 옮겨** 풀었다
(`lib/operator-ready.ts`, `server-only`). 가짜 문구를 넣어 **가드가 실제로 막는 것도 확인**했다.

**② 스마트스토어 골격 → 실연동.** 정독해 보니 네 군데가 성공을 사칭하고 있었다.
`publish()` 가 아무 데도 안 올리고 `ok:true`+가짜 링크 · `issueToken()` 이 **bcrypt 서명을 안 붙이고**
`res.ok` 도 안 봐서 토큰 없이 `connected` · `registry.actions` 가 코드 0줄인 기능을 고객 화면에 약속 ·
`saveChannelKey()` 가 키를 눌러 보지도 않고 `connected`.
→ 전부 실호출로 바꾸고, **못 하는 건 못 한다고** 말하게 했다(스마트스토어엔 글 올리는 API 가 없다).
`fetchMetrics` 로 주문 건수·매출을 가져온다. 테스트 17건 + **돌연변이 주입으로 테스트가 진짜 잡는 것까지 확인**.
⚠️ 실제 판매자 키가 없어 **네이버 서버 왕복은 미검증** — 첫 고객이 키를 넣는 순간 판정된다.
